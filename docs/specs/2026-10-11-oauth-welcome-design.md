# Вход через OAuth на первом экране — спека

Дата: 2026-10-11. Переносит вход через OAuth из настроек и блока токена на первый экран нового пользователя и даёт постоянное место для подключения второго аккаунта. Базовые спеки: `2026-10-09-oauth-design.md` (сам вход), `2026-10-06-first-run-ux-design.md` (пустое состояние, диалог «Добавить проект»), `2026-10-08-onboarding-design.md` (жираф). Здесь только отличия. Макеты обсуждения — `.superpowers/brainstorm/` (не коммитятся).

## 1. Цель и рамки

Новый пользователь входит через GitHub или GitLab с первого экрана и сразу выбирает проект. Пользователь с одним аккаунтом видит, где подключить второй, не заходя в настройки.

Делается:

- экран приветствия вместо пустого состояния `HomePage`;
- шаг «Выберите проект» сразу после входа;
- блок «Аккаунты» внизу сайдбара и диалог «Подключить аккаунт»;
- «+ Другой аккаунт…» в выборе хоста диалога «Добавить проект».

Не делается: изменения в `core` и командах Tauri; аватар или имя пользователя (команды их не отдают); несколько аккаунтов на одном хосте (одна запись связки ключей на хост); экран «Готово»; флаг «приветствие показано» в настройках.

Опыт других приложений, на который опирается дизайн: GitHub Desktop (вход первым экраном, «Skip», после входа список репозиториев), VS Code (Device Flow: «Copy & Continue to GitHub», Accounts внизу слева), Slack и Discord (аккаунты внизу сайдбара), GitKraken и Tower (кнопки провайдеров с логотипами, отдельный путь для self-hosted).

## 2. Какой экран показывает `/`

Чистая функция `homeStep(projectCount, hostCount)` в `pages/home/model/step.ts`:

| Проекты | Хосты (`hostsQuery`) | Шаг |
|---|---|---|
| нет | нет | `welcome` — приветствие, шаг «Вход» |
| нет | есть | `pick` — «Выберите проект» |
| есть | любые | `redirect` — последний открытый проект, как сейчас |

Хосты из `gh`, `glab` и env тоже считаются: такой пользователь попадает сразу на `pick`. Пока список проектов или `hostsQuery` не загружены — «Загрузка…», как сейчас. Ошибка `hostsQuery` — хостов ноль (`welcome`), чтобы сбой чтения связки ключей не блокировал вход.

## 3. Экран приветствия

Одна карточка по центру `main`, ширина ~320px:

- жираф (`Giraffe`, 96px), заголовок «Добро пожаловать в Longpole», одна строка: «Войди, чтобы видеть свои пайплайны и находить, что тормозит сборку» (русские строки — на «ты», как в приложении);
- `ConnectAccount` (§ 5);
- ссылка «Пропустить» — `openAddProject()`; экран приветствия остаётся под диалогом.

## 4. Шаг «Выберите проект»

Та же карточка, шире (~480px): заголовок «Выбери проект на {host}», `ProjectsPanel` для этого хоста, ссылка «Вставить ссылку или выбрать папку» — `openAddProject()`. Выбор проекта — `useAddProject().add(\`https://${host}/${fullPath}\`)`; успех ведёт на экран проекта (как в диалоге), ошибка — текст с жирафом под списком.

Хост — `useHostState().tokenHost`: `useOauthLogin` и `useSaveToken` после успеха уже инвалидируют `hostsQuery` и вызывают `pickHost`, так что это только что подключённый хост, а без выбора — первый сохранённый. Переключение `welcome` → `pick` происходит само: `homeStep` пересчитывается по новому списку хостов.

## 5. `ConnectAccount`

`features/manage-token/ui/ConnectAccount.tsx`, пропсы `{ onConnected?: () => void }`. Состояния:

- **Выбор** — кнопки одной ширины: «Войти через GitHub» (тёмная, логотип), «Войти через GitLab» (outline с оранжевым логотипом: белый текст на `#fc6d26` даёт ≈2,9:1 при требуемых 4,5:1), «Другой сервер…» (outline). Под ними строка «🔒 Только чтение · токен хранится в связке ключей» и ссылка «Вставить токен вручную».
- **GitHub, ждём код** — `useOauthLogin('github.com')`. Крупный `userCode` (`select-all`), главная кнопка «Скопировать код и открыть github.com» — копирует код и открывает `verificationUri`; ссылка «Установить на организацию» (`GITHUB_APP_INSTALL`); индикатор ожидания; «Отмена».
- **GitLab, ждём браузер** — `useOauthLogin('gitlab.com')`, браузер открывает ядро. Текст «Подтвердите вход в браузере», индикатор, «Отмена».
- **Другой сервер** — `TokenForm` с пустым хостом: поле адреса, `OauthLogin` (Client ID, ссылка на регистрацию приложения) и форма PAT. Ссылка «← Назад» к выбору.
- **Токен вручную** — то же, что «Другой сервер»: `TokenForm` уже содержит и OAuth, и PAT. Отдельного состояния нет, ссылка ведёт туда же.
- **Ошибка** — жираф `oops` и `errorText` под кнопками; повтор — той же кнопкой. Отмена возвращает к выбору без сообщения.

Успех любого пути — `onConnected()`.

Состояние ожидания (код GitHub, «завершите в браузере», отмена) сейчас живёт в `OauthLogin`; оно выносится в `OauthWaiting.tsx`, и его используют оба компонента. Поведение `OauthLogin` и `TokenForm` не меняется.

## 6. Второй аккаунт

**Блок «Аккаунты»** — внизу `ProjectsSidebar`, прижат к низу. Строки из `hostsQuery`: иконка провайдера (GitHub, GitLab или нейтральная при `provider === null`), хост, мелко источник (`form.settings.source.*`). Клик по строке — `/settings`. Последняя строка — «+ Подключить», открывает `ConnectDialog`. При пустом списке блок показывает только «+ Подключить».

**`ConnectDialog`** — `widgets/connect-dialog`, стор открытия по образцу `features/add-project/model/dialog.ts` (`openConnect`, `closeConnect`). Внутри — заголовок «Подключить аккаунт» и `ConnectAccount`; `onConnected` переводит диалог на шаг «Выберите проект» (§ 4); выбор проекта закрывает диалог. Закрыть диалог можно на любом шаге.

**Диалог «Добавить проект»** — пункт «+ Добавить хост…» в `HostSelect` получает текст «+ Другой аккаунт…»: «Добавить проект» закрывается и открывается `ConnectDialog` (два модальных диалога рядом спорят за фокус); `pickAddHost()` удаляется. После подключения `HostSelect` показывает новый хост — `pickHost` уже вызван.

**Настройки → Хосты** не меняются: удаление и подробности остаются там.
