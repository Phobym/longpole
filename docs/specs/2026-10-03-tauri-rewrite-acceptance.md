# Чек-лист приёмки: pipeline-trace на Tauri 2 + React

Ручная приёмка переписанного приложения (Electron 0.1.0 → Tauri 2 + React 0.2.0). Сверяется **поведение, а не пиксели**: экраны, клавиши, тексты, числа. Внешний вид новый (shadcn/ui), поэтому расположение и стили элементов не проверяются.

**Когда и на чём.** Чек-лист проходится на артефактах `release.yml`, собранных через `workflow_dispatch` (без тега и релиза), **до** коммита удаления `src/`, `bin/`, `desktop/` и `desktop.yml`. Порядок: артефакты → проход чек-листа → коммит удаления → тег `v0.2.0` → черновик релиза → запуск артефактов → публикация.

**Если пункт не прошёл** — issue с меткой `bug`. Он блокирует удаление старого кода, пока пользователь осознанно не перенесёт пункт в раздел 4 «Осознанные отступления».

**Охват.**
- Разделы 1–2 — полностью на macOS, интерфейс на русском (тексты в кавычках — дословный эталон из старого кода).
- Те же разделы — смоук на английском (macOS): пункты с меткой `(смоук)`, плюс вычитка английских текстов.
- На Windows и Linux — только пункты `(смоук)` из разделов 1–2.
- Раздел 3 — на всех трёх ОС.
- Разделы 5–6 — на macOS arm64, рядом с установленной 0.1.0.

**Подготовка.** Токен `read_api` для рабочего GitLab; проект, где есть пайплайн с ретраями, ручными джобами, шардами (`name 1/4`), `needs`, downstream-пайплайном (bridge) и `allow_failure`; открытый MR с пайплайном; ветка `master` с 50+ пайплайнами.

Формат пункта: `действие → ожидаемый результат`.

## 1. Форма

### 1.1. История

- [ ] Первый запуск 0.2.0 → в колонке «История» текст «Пока пусто», кнопки «Очистить» нет.
- [ ] Построить отчёт по ссылке → в истории появилась запись: подпись `<группа>/<проект> · #<iid>`, под ней хост и дата-время коротким форматом локали.
- [ ] Построить агрегат по ветке `master` → запись `<группа>/<проект> · master`; агрегат без ветки → запись `<группа>/<проект> · все пайплайны`.
- [ ] Неудачная сборка (ошибка в ссылке, нет пайплайнов) → запись в историю не добавляется.
- [ ] Повторить тот же запрос → дубль не появляется, запись поднимается наверх с новым временем.
- [ ] Построить 21 разный отчёт → в истории ровно 20 записей, самая старая вытеснена.
- [ ] Клик по записи режима «ссылка» (в т.ч. с экрана «Проект») → открыт экран «Проекты», в поле ссылки подставлен URL записи, фокус в этом поле. (смоук)
- [ ] Клик по записи режима «агрегат» → открыт экран «Проект»: заголовок — путь проекта (`group/project`, не имя), ветка, «Сколько пайплайнов» и статусы — из записи, кнопка «Агрегат по N пайплайнам» с N из записи.
- [ ] Запись агрегата со статусом «любой» → «любой» отмечен, остальные чекбоксы сняты и неактивны.
- [ ] Кнопка «×» у записи → удаляется только эта запись, запись при этом не открывается; у кнопки доступное имя «Удалить из истории: <подпись>».
- [ ] «Очистить» → диалог «Очистить историю запросов?»; «Отмена» → история не изменилась.
- [ ] «Очистить» → подтвердить → «Пока пусто», кнопка «Очистить» скрыта.
- [ ] Перезапустить приложение → история сохранилась (лежит в `app_data_dir`).
- [ ] Записи истории не содержат токен: открыть `history.json` в каталоге данных приложения → только поля `mode`, `host`, `url`, `project`, `ref`, `source`, `last`, `statuses`, без токена.

### 1.2. Проекты: ссылка

- [ ] Поле «Вставь ссылку на пайплайн или MR» с подсказкой `https://gitlab.example.com/group/project/-/pipelines/123…` и кнопкой «Построить».
- [ ] Вставить ссылку `…/-/pipelines/<id>` → «Построить» → кнопка неактивна, текст меняется на «Загружаю 0 из 1…» → «Загружаю 1 из 1…»; открылось окно отчёта; кнопка вернула текст «Построить». (смоук)
- [ ] Ссылка на MR `…/-/merge_requests/<iid>` → открыт отчёт по head-пайплайну MR.
- [ ] Ссылка с хвостом (`…/-/pipelines/123/builds`, `?tab=…`) → отчёт строится.
- [ ] Пустое поле или `foo` → под полем «Нужна ссылка вида https://<хост>/<группа>/<проект>/-/pipelines/<id> или …/-/merge_requests/<iid>», окно не открывается.
- [ ] Ссылка на несуществующий пайплайн → «Пайплайн gid://gitlab/Ci::Pipeline/<id> в проекте <проект> на <хост> не найден» (формат id — как в 0.1.0).
- [ ] Ссылка на чужой/несуществующий проект → «Проект <проект> на <хост> не найден или нет доступа».
- [ ] MR без пайплайна → «У MR !<iid> в проекте <проект> нет пайплайна».
- [ ] Ссылка на хост без токена (нет ни в хранилище, ни в `glab`, ни в env) → «Нет токена для <хост>: добавь его в форме (поле «Токен»)».
- [ ] Отозванный токен → «GitLab <хост> ответил 401: токен недействителен или нет доступа».

### 1.3. Проекты: хост и токен

- [ ] Нет сохранённых хостов → в списке «Хост» выбран «+ Добавить хост…», видна подсказка «Добавь токен для этого хоста, чтобы смотреть список проектов.» и подформа «Хост»/«Токен»/«Сохранить токен»; панели проектов нет.
- [ ] Ввести хост и токен → «Сохранить токен» → поле токена очищено, в списке выбран `<хост> — токен сохранён`, подформа скрыта, появилась кнопка «Удалить токен» и список проектов. (смоук)
- [ ] Поле токена — тип пароля, без автозаполнения и проверки орфографии.
- [ ] Хост `https://gitlab.example.com/` → сохраняется как `gitlab.example.com`.
- [ ] Хост `bad host!` → «Укажи хост GitLab, например gitlab.example.com», токен не сохранён.
- [ ] Пустой токен или из пробелов → «Пустой токен».
- [ ] Несколько сохранённых хостов → в списке по алфавиту, при запуске выбран первый.
- [ ] Переключить хост в списке → список проектов перезагружается под новый хост, поле поиска очищено.
- [ ] «Удалить токен» → диалог «Удалить токен для <хост>?»; «Отмена» → ничего не изменилось.
- [ ] «Удалить токен» → подтвердить → хост пропал из списка, выбран первый оставшийся или «+ Добавить хост…».
- [ ] Токен не виден в интерфейсе: после сохранения его нельзя прочитать ни в одном поле.
- [ ] Хост без сохранённого токена, но с токеном в `glab` → сборка по ссылке работает (токен берётся из `glab config get token --host <хост>`).
- [ ] Только `GITLAB_TOKEN` + `GITLAB_HOST=<хост>` в окружении (запуск из терминала) → сборка по ссылке на этот хост работает; на другой хост — «Нет токена для …».

### 1.4. Проекты: поиск и список

- [ ] С сохранённым токеном → пока грузится, статус «Загрузка…»; затем список проектов, в которых пользователь участник, по последней активности.
- [ ] Строка проекта → имя с группой, полный путь, чип основной ветки (если есть), «активность <относительное время>» («вчера», «3 дня назад» и т.п.).
- [ ] Ввести текст в «Поиск проекта» (подсказка «Название или путь…») → запрос уходит через 300 мс после последнего нажатия, а не на каждую букву.
- [ ] Быстро напечатать и стереть часть запроса → в списке результаты последнего запроса, без смешивания с ответами на промежуточные.
- [ ] Поиск без совпадений → «Ничего не найдено».
- [ ] Ввести поиск, открыть проект, «← Проекты» → текст поиска и список на месте.
- [ ] Больше 20 проектов → под списком «Показать ещё»; клик → добавились следующие 20, старые остались; на последней странице кнопки нет.
- [ ] Ошибка загрузки (например, отозванный токен) → текст ошибки над списком, «Показать ещё» скрыта.
- [ ] Клик по проекту → экран «Проект».

### 1.5. Проект: ветка

- [ ] Открыть проект из списка → заголовок — имя проекта, кнопка «← Проекты», в поле «Ветка» — основная ветка проекта.
- [ ] Подсказки веток → до 20 штук, основная ветка первой.
- [ ] Ввести часть имени ветки → подсказки обновляются через 300 мс по вхождению подстроки.
- [ ] Выбрать другую ветку → список пайплайнов перезагружается для неё.
- [ ] Очистить ветку → список пайплайнов по всем веткам.
- [ ] Ввести ветку, которой нет в подсказках → принимается, пайплайнов нет → «Ничего не найдено».
- [ ] Пока печатаешь ветку, список пайплайнов не перезагружается; перезагрузка — при выборе подсказки, по Enter или при уходе фокуса, если значение изменилось.
- [ ] «← Проекты» → экран «Проекты».
- [ ] Esc на экране «Проект» → экран «Проекты». (смоук)
- [ ] Esc на экране «Проекты» → ничего не происходит.
- [ ] На экране «Проект» открыт Combobox веток → первый Esc закрывает его, экран остаётся; второй Esc → «Проекты».

### 1.6. Проект: пайплайны

- [ ] Список последних пайплайнов ветки, пока грузится — «Загрузка…».
- [ ] Строка пайплайна → `#<iid>`, статус-пилюля (success — зелёная, running/pending — синяя, failed — красная, manual/canceled/skipped/created — жёлтая), заголовок коммита (или «—»), автор (или «—»), относительное время создания, длительность в формате формы (`45s`, `12m05s`, `1h02m`, «—» если нет).
- [ ] Больше 20 пайплайнов → «Показать ещё» догружает следующие 20.
- [ ] Клик по строке → строка неактивна, в ней «Загружаю…», затем «Загружаю N из M…»; открылось окно отчёта по этому пайплайну; статус в строке скрылся.
- [ ] Ошибка сборки по строке → текст ошибки остаётся в этой строке красным, строка снова активна.
- [ ] Открыть проект A, затем вернуться и открыть проект B → в списке только пайплайны B (запоздавший ответ A не подмешивается).
- [ ] Ошибка загрузки списка → текст ошибки, «Показать ещё» скрыта.

### 1.7. Проект: агрегат

- [ ] По умолчанию «Статусы»: отмечены SUCCESS и MANUAL; FAILED, CANCELED, RUNNING и «любой» сняты.
- [ ] Отметить «любой» → остальные статусы сняты и неактивны; снять «любой» → статусы снова активны (все сняты).
- [ ] Снять все статусы → «Агрегат по …» → под статусами «Выбери хотя бы один статус или «любой»».
- [ ] «Сколько пайплайнов» по умолчанию 50, кнопка «Агрегат по 50 пайплайнам».
- [ ] Ввести 120 → кнопка сразу «Агрегат по 120 пайплайнам»; очистить поле → «Агрегат по 0 пайплайнам»; ввести 1 → «Агрегат по 1 пайплайну», 21 → «Агрегат по 21 пайплайну» (склонение — отступление, раздел 4).
- [ ] N = 0, 501, 2.5 или пусто → «Число пайплайнов — от 1 до 500», сборка не начинается.
- [ ] N = 1 → агрегат по одному пайплайну строится.
- [ ] N = 500 → проходит проверку (сборку можно прервать закрытием окна отчёта после открытия).
- [ ] «Агрегат по 50 пайплайнам» на `master` → кнопка неактивна, «Загружаю N из 50…» растёт; открылось окно агрегата; кнопка вернула прежний текст. (смоук)
- [ ] Фильтры, под которые не попал ни один пайплайн (ветка без пайплайнов + только CANCELED) → «Под фильтры не попал ни один пайплайн: проверь ветку и статусы» под кнопкой.
- [ ] Нет сети или хост недоступен → «Не удалось связаться с GitLab <хост>: <текст ошибки>».
- [ ] Статусы и N, изменённые в проекте A, сохраняются при открытии проекта B; меняет их только запись истории.
- [ ] Перезапуск приложения → N снова 50, статусы по умолчанию.

### 1.8. Язык

- [ ] Системная локаль `ru*` → при первом запуске форма и меню на русском; любая другая → на английском.
- [ ] Переключатель «RU / EN» в форме → форма сразу перерисовывается на выбранном языке без перезапуска. (смоук)
- [ ] После переключения → меню приложения пересобрано на новом языке.
- [ ] Окна отчётов, открытые до переключения, не меняют язык.
- [ ] Отчёт, построенный после переключения на EN, открывается на английском.
- [ ] Перезапуск → выбранный язык сохранился (`settings.json` в `app_data_dir`).
- [ ] На EN ошибки валидации и GitLab (неверная ссылка, N вне диапазона, нет статусов, 401, проект не найден) — по-английски; текст GraphQL-ошибки от GitLab приходит как есть внутри английской фразы.
- [ ] На EN относительное время, даты и числа — в английском формате; длительности (`12s`, `1m05s`) те же, что на RU.
- [ ] Вычитка: пройти все экраны формы на EN → нет русских строк, ключей словаря вместо текста, обрезанных подписей.

## 2. Отчёт

Проверять на трёх отчётах: одиночный пайплайн (по ссылке), он же открытый из агрегата, агрегат по 50 пайплайнам.

### 2.1. Шапка

- [ ] Одиночный → заголовок `<проект> · #<iid>`, `#<iid>` — ссылка на пайплайн в GitLab.
- [ ] Одиночный → чипы: ref, статус, «<длина> длина», «ретраи <время>», «можно сэкономить до <время>», «<N> джоб/джобы/джоба» (склонение по числу).
- [ ] Агрегат → заголовок `<проект> · <ветка>` (без ветки — «все пайплайны»), без ссылки.
- [ ] Агрегат → чип «<N> пайплайнов (<k> success, <m> manual)» со склонением и счётчиками статусов в нижнем регистре; чип «<p50> · <p90> длина p50 · p90».
- [ ] Чип «ретраи» красный при потерях > 0, обычный при `0s`; «можно сэкономить до» оранжевый при > 0.
- [ ] «можно сэкономить до» = сумма пунктов «Куда направить силы».
- [ ] Заголовок окна отчёта — `<проект> · <метка>`, не меняется при переходах внутри отчёта; во вкладке браузера у сохранённого файла — `pipeline-trace · <заголовок>`.
- [ ] Кнопки «← к агрегату» нет в агрегате и в отчёте по ссылке.

### 2.2. «Куда направить силы»

- [ ] Карточка «Куда направить силы» → не больше 3 пунктов, каждый с экономией от 10 с, по убыванию экономии.
- [ ] Нет кандидатов → карточки нет вовсе.
- [ ] Пункт → «−<экономия> <джоба> — <причина>».
- [ ] Причина превышения в одиночном → «стейдж <S> ждёт её <время> после остальных, на критическом пути»; в агрегате — без «, на критическом пути».
- [ ] Причина ретраев в одиночном → «<n> упавшая попытка / упавшие попытки / упавших попыток»; в пайплайне, открытом из агрегата, добавлено «, ретраи в k из N последних».
- [ ] Причина ретраев в агрегате → «ретраи в k из N пайплайнов».
- [ ] В карточку попадают только джобы критического пути.
- [ ] Клик по пункту → джоба выделена, свёрнутая группа с ней развернута, строка прокручена в центр и в фокусе, открыта панель.

### 2.3. Водопад: ось

- [ ] Ось начинается с `0s` (создание пайплайна), деления не чаще 10 на видимый интервал, шаг из ряда 1s, 5s, 10s, 30s, 1m, 2m, 5m, 10m, 15m, 30m, 1h, 2h.
- [ ] Подписи делений в формате отчёта (`30.0s`, `1m00s`, `1h00m`), при зуме шаг мельчает.

### 2.4. Водопад: карточки стейджей

- [ ] Каждый стейдж — карточка с заголовком-строкой стейджа.
- [ ] Одиночный → в заголовке «длина <X>» (от старта первой джобы до конца последней) и «до конца <X>» (от создания пайплайна).
- [ ] Агрегат → «длина <p50> · <p90>», «до конца <p50> · <p90>», подсказка при наведении «p50 · p90».
- [ ] Стейдж с узким местом → в начале «держит <джоба> +<превышение>».
- [ ] Незапущенный стейдж в одиночном → без «длина»/«до конца».
- [ ] Downstream-пайплайн внутри bridge → строки дочернего пайплайна разрывают карточку стейджа, остаток стейджа продолжается карточкой без заголовка.

### 2.5. Водопад: строки

- [ ] Иерархия: пайплайн → стейджи → группы/джобы → bridge → дочерний пайплайн; отступ растёт с глубиной.
- [ ] При открытии отчёта все группы шардов свёрнуты, у группы `▸` и число детей.
- [ ] Клик по `▸` → группа развёрнута, `▾`; повторный клик сворачивает; клик по стрелке не выделяет строку.
- [ ] У стрелки доступное имя «Развернуть <имя>» / «Свернуть <имя>».
- [ ] Джоба, которая ждала соседа по стейджу, стоит сразу после него с подписью «← <сосед>».
- [ ] Длинное имя обрезано, полное — в подсказке при наведении.
- [ ] Справа у джобы в агрегате и в пайплайне из агрегата — метка стабильности: «стабильна» (зелёная), «↻ k из N» жёлтая (< 30% запусков) или красная (≥ 30%), подсказка «ретраи в k из N пайплайнов».
- [ ] В пайплайне, открытом по ссылке (без агрегата), меток стабильности нет.
- [ ] Строки критического пути выделены оранжевым; группа выделена, если на пути её шард.
- [ ] Агрегат → выделены узлы, бывшие на критическом пути в ≥ 50% пайплайнов.
- [ ] Агрегат, группа шардов, у которой каждый шард < 50%, а в сумме ≥ 50% → строка группы не выделена, а панель показывает «крит. путь ≥ 50%» (причуда сохранена).

### 2.6. Водопад: бары, попытки, метки, превышение

- [ ] Одиночный → полоска джобы от старта до конца, цвет по статусу; упавшая с `allow_failure` — предупреждающим цветом, а не красным.
- [ ] Строка пайплайна и группы → тонкая полоска.
- [ ] Серая полоска перед джобой → ожидание раннера (очередь).
- [ ] Ретраи → упавшие попытки красной штриховкой, серая черта между ними — ожидание; подпись «<длительность> · ↻<n> −<потери>».
- [ ] Оранжевый пунктир перед джобой критического пути → ожидание между джобами пути.
- [ ] Незапущенная джоба → подпись «не запускалась · <статус>» слева, без полоски.
- [ ] Агрегат → полоска от p50 старта длиной p50 длительности, линия-«ус» до p90; подпись «<p50> · ↻ k/N» при ретраях.
- [ ] Агрегат, джоба запускалась не во всех пайплайнах → полоска полупрозрачная.
- [ ] Агрегат, джоба не запускалась ни разу → «не запускалась».
- [ ] Превышение → в карточке стейджа пунктирная вертикаль в момент конца остальных джоб; у последней джобы хвост правее вертикали заштрихован, в подписи «+<превышение>».
- [ ] Подпись бара у правого края (полоска кончается правее 80% ширины) → переносится левее начала полоски, не обрезается.
- [ ] Длительности в отчёте: `850ms`, `12.3s`, `1m05s`, `1h02m`, ровно ноль — `0s`, нет данных — «—».

### 2.7. Панель деталей

- [ ] Клик по строке → справа панель, водопад сужается; повторный клик по другой строке → панель переключается.
- [ ] Шапка панели → имя; под ним «стейдж <S>»; в агрегате у джобы ещё «запускалась в k из N».
- [ ] Чипы: метка стабильности; в одиночном у джобы статус («failed · allow_failure» для разрешённого падения, красный для обычного failed); «на критическом пути» / «не на критическом пути» (в агрегате «крит. путь <доля>%», оранжевый от 50%).
- [ ] Вывод джобы на пути (одиночный) → «На критическом пути: ускорение сократит пайплайн.»; вне пути → «Не на критическом пути: ускорение не сократит пайплайн.».
- [ ] Вывод в агрегате → «На критическом пути в <доля>% пайплайнов: ускорение сократит (≥ 50%) / иногда сокращает (< 50%) пайплайн.».
- [ ] Джоба из «Куда направить силы» → в выводе «Экономия до −<время>.»; узкое место → «Держит стейдж <S> на +<время>.».
- [ ] Ретраи в выводе: одиночный → «<n> упавшие попытки, потеряно <время>.»; агрегат → «Стоит посмотреть ретраи — k из N.».
- [ ] Стейдж → «Держит <джоба> +<время>.» (если есть) и в одиночном «Критический путь до конца стейджа выделен в водопаде.»; пайплайн в одиночном → «Критический путь выделен в водопаде.».
- [ ] Показатели «Длительность», «Старт», «До конца»; в агрегате значение p50 и строка «p90 <время>».
- [ ] Агрегат, джоба → раздел «Длительность по N пайплайнам»: точка на каждый пайплайн, красные — с ретраями, отметки p50 и p90; подсказка точки «#<iid> <длительность>» (+ « · ретраи»).
- [ ] Клик по точке → открыт этот пайплайн (см. 2.11).
- [ ] Раздел «Стабильность» одиночный → «Попытки» (ссылки на попытки со статусом и длительностью), «Потери», «Очередь».
- [ ] Раздел «Стабильность» агрегат → «Ретраи: в k из N пайплайнов», «Потери: <время> в среднем», «Очередь: p50 <X> · p90 <Y>».
- [ ] Одиночный → внизу «Открыть в GitLab ↗».
- [ ] Агрегат → «Самые долгие»: 5 пайплайнов по убыванию длительности, у каждого имя-кнопка, полоска (красная — с ретраями), время, «GitLab ↗».
- [ ] Больше 5 → кнопка «Все N пайплайнов ▾» → показаны все, кнопка «Свернуть ▴», фокус остаётся на кнопке, `aria-expanded` меняется.
- [ ] Развернуть «Все N…», выбрать другую строку → у неё снова 5 пайплайнов.
- [ ] «×» в панели (доступное имя «Закрыть») → панель закрыта, выделение снято, водопад во всю ширину.

### 2.8. Связи и линии

- [ ] Клик по джобе → джобы, которых она ждала, помечены «↑ нужна для <джоба>»; джобы, которые ждут её, — «↓ ждёт <джоба>»; из любых стейджей.
- [ ] Линии: синие со стрелкой — от джоб, которых она ждала; зелёные — к джобам, которые ждут её; идут от конца полоски источника к началу полоски цели.
- [ ] Связанная джоба внутри свёрнутой группы → подсвечена и соединена линией строка группы.
- [ ] Выбор группы → связи по всем её шардам.
- [ ] Выбор стейджа или пайплайна → ни меток, ни линий.
- [ ] В панели раздел «Связи» → кнопки «↑ <имя>» и «↓ <имя>»; клик → эта джоба выделена, родительские группы развёрнуты, строка прокручена в центр.
- [ ] Свернуть/развернуть группу, сдвинуть ось → линии перерисованы на новых местах.
- [ ] Esc → метки и линии пропали.

### 2.9. Помощь `?`

- [ ] Кнопка `?` (доступное имя «Управление») → список из 6 строк: перетаскивание, `Shift` + колесо, `[` `]` — сдвиг оси; `⌘`/`Ctrl` + колесо или pinch — масштаб, горизонтальный свайп — сдвиг, `0` — весь пайплайн; `↑` `↓` — соседняя строка, `Enter` — выбрать; `←` `→` — свернуть и развернуть; клик по стейджу — критический путь до его конца; клик по джобе — её связи, `Esc` — снять выделение.
- [ ] Повторный клик по `?`, клик вне подсказки или Esc → подсказка закрыта; клик внутри подсказки её не закрывает.

### 2.10. Клавиши и жесты

- [ ] `]` → ось сдвинута вправо на 10% видимого интервала; `[` → влево на 10%.
- [ ] `[` у начала → ось не уходит левее `0s`.
- [ ] `0` → виден весь пайплайн (в агрегате — до p90 конца).
- [ ] Клавиши с ⌘/Ctrl/Alt (например, ⌘0, ⌘]) → отчёт их не обрабатывает.
- [ ] Tab до строки, `↓`/`↑` → фокус на соседней строке; `Enter` → строка выбрана, панель открыта.
- [ ] `←` на строке с детьми → свёрнута, `→` → развёрнута; на строке без детей ничего.
- [ ] Esc → выделение снято, панель закрыта, подсказка `?` закрыта. (смоук)
- [ ] Клик по строке → строка в фокусе (дальше работают стрелки).
- [ ] Перетаскивание по дорожке левой кнопкой → ось едет за мышью, вправо — к началу, не левее `0s`. (смоук)
- [ ] Сдвиг мыши меньше 4 px с нажатой кнопкой и отпускание → это клик: строка выбирается, ось не двигается.
- [ ] Перетащить больше 4 px и отпустить над строкой → выделение не меняется.
- [ ] Перетаскивание по колонке имён → ось не двигается.
- [ ] ⌘/Ctrl + колесо над дорожкой → масштаб вокруг точки под курсором (точка остаётся под курсором). (смоук)
- [ ] Pinch на тачпаде → то же, что ⌘ + колесо.
- [ ] Максимальное приближение → не меньше 1 с на всю ширину; максимальное отдаление → не больше всего пайплайна.
- [ ] Shift + колесо и горизонтальный свайп над дорожкой → сдвиг оси.
- [ ] Обычное вертикальное колесо → прокрутка страницы, ось не меняется.
- [ ] Жесты над колонкой имён → зум не срабатывает.
- [ ] Агрегат на 50 пайплайнов, все группы развёрнуты → перетаскивание и зум без заметных рывков.

### 2.11. Агрегат ↔ пайплайн

- [ ] Клик по точке или имени в «Самые долгие» → открыт этот пайплайн: шапка одиночного, все группы свёрнуты, выделение снято, ось на весь пайплайн.
- [ ] В этом пайплайне → кнопка «← к агрегату», метки стабильности есть.
- [ ] «← к агрегату» → снова агрегат, состояние сброшено (группы свёрнуты, без выделения, ось на весь агрегат).
- [ ] Ссылка «GitLab ↗» в «Самые долгие» → открывает GitLab в браузере, а не пайплайн в отчёте.

### 2.12. Выбор стейджа и критический путь (одиночный)

- [ ] Клик по стейджу → оранжевый путь пересчитан до конца этого стейджа.
- [ ] Клик по строке пайплайна → путь всего пайплайна.
- [ ] Клик по строке дочернего (downstream) пайплайна или его стейджа → путь внутри него.
- [ ] Клик по bridge или джобе → путь не меняется.
- [ ] Агрегат: клик по стейджу → выделение пути не меняется.

### 2.13. Язык отчёта

- [ ] Отчёт, построенный на RU, открывается на русском; на EN — на английском (`meta.locale`).

- [ ] Склонения на RU (1 джоба / 2 джобы / 5 джоб, 1 пайплайн / 3 пайплайна / 11 пайплайнов, 21 упавшая попытка) и формы множественного числа на EN.
- [ ] Вычитка английского отчёта: нет русских строк и ключей словаря.

### 2.14. Сохранение ⌘/Ctrl+S

- [ ] В окне отчёта ⌘S → системный диалог сохранения, имя по умолчанию `pipeline-trace-<проект>-<id>.html` (`/` и пробелы в пути → `-`), фильтр HTML. (смоук)

- [ ] Сохранить → файл записан, окно отчёта продолжает работать.
- [ ] Сохранение в каталог без прав записи → окно ошибки «Не удалось сохранить отчёт» с причиной.
- [ ] Два отчёта: ⌘S в каждом → сохраняется именно этот отчёт (своё имя по умолчанию).
- [ ] Меню «Файл → Сохранить отчёт…» из окна отчёта → то же, что ⌘S.

### 2.15. Сохранённый файл в браузере

- [ ] Открыть сохранённый файл двойным кликом в Chrome, Safari и Firefox → отчёт отрисован, стили на месте, светлая/тёмная тема по системе.
