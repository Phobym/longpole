# pipeline-trace

Показывает, на что уходит время GitLab-пайплайна: водопад стейджей и джоб в стиле трейсов Sentry, критический путь и p50/p90 по многим пайплайнам. Результат — один HTML-файл без внешних запросов.

## Как читать отчёт

- Чипы в шапке: длина пайплайна (в агрегате — p50 · p90), время, потерянное на ретраях, и «можно сэкономить до» — сумма пунктов карточки «Куда направить силы». Кнопка `?` показывает клавиши и жесты.
- Карточка «Куда направить силы» — до трёх пунктов с экономией от 10 с. В неё попадают только джобы критического пути: остальные длину пайплайна не меняют. Клик по пункту выделяет джобу и прокручивает к ней.
- Каждый стейдж — карточка. В заголовке: `держит build:server +1m00s` — узкое место стейджа, затем `длина` (от старта первой джобы до конца последней) и `до конца` (от создания пайплайна до конца стейджа).
- Превышение: пунктирная вертикаль в карточке стейджа — момент, когда закончились все джобы, кроме последней. У последней джобы часть полоски правее вертикали заштрихована, подпись `+1m00s`.
- Ретраи: упавшие попытки нарисованы красной штриховкой в строке джобы, серая черта между ними — ожидание. Подпись `↻2 −8m29s` — число упавших попыток и потерянное на них время. В агрегате `↻ 3/8` — ретраи были в 3 из 8 запусков.
- Метка справа — стабильность джобы по пайплайнам агрегата: зелёная «стабильна», жёлтая «↻ k из N» — ретраи меньше чем в 30% запусков, красная — от 30%. В пайплайне, открытом по ссылке без агрегата, меток нет.
- Оранжевые полоски — критический путь. Клик по стейджу пересчитывает путь до его конца. Оранжевый пунктир — ожидание между джобами пути.
- Внутри стейджа джоба стоит сразу после соседа, которого ждала; подпись `← build:server` называет этого соседа. Зависимости из других стейджей на порядок не влияют.
- Клик по джобе рисует линии к её прямым связям: синие — от джоб, которых она ждала, зелёные — к джобам, которые ждут её. Без выбранной джобы линий нет.
- Клик по джобе подсвечивает её прямые связи из любого стейджа: `↑ нужна для` — джобы, которых она ждала, `↓ ждёт` — джобы, которые ждут её. Если связанная джоба в свёрнутой группе, подсвечивается группа. Esc снимает подсветку.
- Серая черта перед полоской — очередь раннера. В агрегате полоска начинается в p50 старта и длится p50 длительности, линия после неё дотягивает до p90. Полупрозрачная полоска — джоба запускалась не во всех пайплайнах; p90, число запусков и долю на критическом пути показывает панель деталей.
- Клик по строке открывает панель деталей. Сверху — вывод: сократит ли ускорение пайплайн, сколько можно сэкономить, есть ли ретраи. Дальше длительность, старт и конец (в агрегате p50 и p90), в агрегате — точка на каждый пайплайн (красная — с ретраями, клик открывает пайплайн), стабильность, кнопки связей ↑/↓ и самые долгие пайплайны со ссылками в GitLab.
- Трейс сдвигается перетаскиванием полосок мышью или клавишами `[` и `]`, но не левее начала пайплайна; ⌘/Ctrl + колесо или pinch на тачпаде меняет масштаб вокруг курсора, горизонтальный свайп сдвигает, `0` возвращает весь пайплайн.
- Клавиатура: ↑/↓ — соседняя строка, Enter — выбрать, ←/→ — свернуть и развернуть.

## Приложение

Форма строит отчёт по ссылке или по проекту из списка «Мои проекты». Приложение умеет:

- ссылку на пайплайн или MR — вставляешь в поле в шапке и жмёшь «Построить»;
- «Мои проекты» в сайдбаре: добавление по ссылке на репозиторий, пайплайн или MR, по ssh-URL, по папке с клоном (читается `remote.origin.url`) или из списка проектов хоста; при добавлении проверяется доступ;
- токен запрашивается там, где понадобился: под полем ссылки или в диалоге добавления, со ссылкой на создание Personal Access Token (scope `read_api`); токены из `glab` и `GITLAB_TOKEN` приложение видит само;
- экран проекта — ветка (с подсказками из списка веток), последние пайплайны с переходом в отчёт по клику и агрегат по N пайплайнам с фильтром по статусам;
- отчёт открывается в том же окне: «← Назад» или Esc возвращают к проекту, `Cmd/Ctrl+S` сохраняет HTML; последние 10 отчётов держатся в памяти, повтор из «Недавних» открывается без похода в GitLab;
- при запуске открывается последний проект;
- «Недавние» — история последних 20 запросов с повтором по клику, удалением записи или очисткой;
- настройки (шестерёнка, `Cmd/Ctrl+,`): хосты и токены с источником (связка ключей, `glab`, окружение), тема (системная, светлая, тёмная), язык берётся из системной локали (`ru*` — русский, иначе английский), переключатель RU/EN — в настройках;
- агрегат по статусам: пайплайн, остановившийся на ручной джобе, GitLab помечает `manual`; короткие служебные `success`-пайплайны (например, Publish-коммиты) смешиваются с полными — чтобы их отсечь, оставь только MANUAL.

Сборки — на странице [GitHub Releases](../../releases). Релиз создаётся черновиком по тегу `v*`, версия тега должна совпадать с `version` в `app/package.json`.

| Система | Файл |
|---|---|
| macOS, Apple Silicon | `pipeline-trace_<версия>_aarch64.dmg` |
| macOS, Intel | `pipeline-trace_<версия>_x64.dmg` |
| Windows | `pipeline-trace_<версия>_x64-setup.exe` |
| Linux | `pipeline-trace_<версия>_amd64.AppImage`, `pipeline-trace_<версия>_amd64.deb` |

Zip-архивов больше нет.

Установка без подписи:

- **macOS**: открыть `.dmg`, перетащить `.app` в «Программы». Первый запуск — «Открыть» из контекстного меню правой кнопкой мыши. Если Gatekeeper всё равно блокирует и это macOS 15 или новее — «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть». Не помогло — снять карантин: `xattr -dr com.apple.quarantine "/Applications/pipeline-trace.app"`.
- **Windows**: SmartScreen покажет предупреждение — «Подробнее» → «Выполнить в любом случае». Если в системе нет WebView2, установщик скачает его сам.
- **Linux**: для AppImage — `chmod +x pipeline-trace_*.AppImage`; для deb — `sudo apt install ./pipeline-trace_*.deb`.

Сеть: приложение доверяет сертификатам из системного хранилища и учитывает `HTTP_PROXY`/`HTTPS_PROXY`. Переменная `NODE_EXTRA_CA_CERTS` не поддерживается — корпоративный корневой сертификат надо добавить в системное хранилище.

Токен для хоста ищется в системной связке ключей, затем в `glab`, затем в `GITLAB_TOKEN` вместе с `GITLAB_HOST`. На Linux без Secret Service (`gnome-keyring`, KWallet) сохранить токен нельзя; используй `glab` или переменные окружения.

Токены, история, настройки и список проектов (`projects.json`) хранятся в каталоге данных приложения (у каждой ОС свой путь). Токены и история версии 0.1.0 (Electron) не переносятся.

Разработка (нужен Rust по `app/rust-toolchain.toml`, Node 22+):

```bash
cd app
npm ci
npm run build        # шаблон отчёта нужен сборке Rust
npm run tauri dev
```

Сборка установщика: `npm run tauri build`. Выпуск — тегом `v*` или вручную через `workflow_dispatch` в Actions: тогда артефакты лежат в прогоне, релиз не создаётся.

Проверки ядра: `cargo test -p pipeline-trace-core` в `app/`.
