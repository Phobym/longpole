# Selfhosted без состояния и в одну реплику

У Selfhosted нет базы и нет общего сервисного токена. Каждый пользователь входит в хост через OAuth web flow, и сервер ходит в API от его имени. Токены лежат в зашифрованной cookie сессии, кэш отчётов — в памяти процесса, а «Мои проекты», «Недавние» и настройки — в браузере. Так права пользователя у провайдера остаются единственным источником доступа: отчёт из общего кэша выдаётся только после проверки прав от имени запросившего. Администратору при этом нечего бэкапить и мигрировать.

## Consequences

- Одноразовый refresh-токен GitLab обновляется через in-memory single-flight, поэтому инстанс работает в **одну реплику**. Для нескольких реплик понадобится общее хранилище — это новое решение, а не настройка.
- Ссылку рядом с пайплайном без правки CI (вебхук + commit status) сделать нельзя, для неё нужен сервисный токен. Ссылка приходит из одной строки в CI.
- Кэш и сессии single-flight теряются при рестарте. Это допустимо: отчёт перестраивается, повторный вход тихий.

## Considered Options

- Серверная БД с пользователями и общими проектами — отвергнута как лишняя для пилота.
- Сервисный токен для всех запросов — отвергнут: он раскрыл бы пайплайны тем, у кого нет прав у провайдера.
