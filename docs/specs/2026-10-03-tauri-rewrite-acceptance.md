# Чек-лист приёмки: longpole на Tauri 2 + React

Ручная приёмка переписанного приложения (Electron 0.1.0 → Tauri 2 + React 0.2.0). Сверяется **поведение, а не пиксели**: экраны, клавиши, тексты, числа. Внешний вид новый (shadcn/ui), поэтому расположение и стили элементов не проверяются.

**Когда и на чём.** Чек-лист проходится на артефактах `release.yml`, собранных через `workflow_dispatch` (без тега и релиза), **до** коммита удаления `src/`, `bin/`, `desktop/` и `desktop.yml`. Порядок: артефакты → проход чек-листа → коммит удаления → тег `v0.2.0` → черновик релиза → запуск артефактов → публикация.

**Если пункт не прошёл** — issue с меткой `bug`. Он блокирует удаление старого кода, пока пользователь осознанно не перенесёт пункт в раздел 4 «Осознанные отступления».

**Охват.**
- Разделы 1–2 — полностью на macOS, интерфейс на русском (тексты в кавычках — дословный эталон из старого кода).
- Те же разделы — смоук на английском (macOS): пункты с меткой `(смоук)`, плюс вычитка английских текстов.
- На Windows и Linux — только пункты `(смоук)` из разделов 1–2.
- Раздел 3 — на всех трёх ОС.
- Разделы 5–6 — на macOS arm64, рядом с установленной 0.1.0.

**Подготовка.** Токен `read_api` для рабочего GitLab; проект, где есть пайплайн с ретраями, ручными джобами, шардами (`name 1/4`), `needs`, downstream-пайплайном (bridge) и `allow_failure`; открытый MR с пайплайном; ветка `master` с 50+ пайплайнами.

Формат пункта: `действие → ожидаемый результат`.

## 1. Форма

### 1.1. История

- [x] Первый запуск 0.2.0 → в колонке «История» текст «Пока пусто», кнопки «Очистить» нет.
- [x] Построить отчёт по ссылке → в истории появилась запись: подпись `<группа>/<проект> · #<iid>`, под ней хост и дата-время коротким форматом локали.
- [x] Построить агрегат по ветке `master` → запись `<группа>/<проект> · master`; агрегат без ветки → запись `<группа>/<проект> · все пайплайны`.
- [x] Неудачная сборка (ошибка в ссылке, нет пайплайнов) → запись в историю не добавляется.
- [x] Повторить тот же запрос → дубль не появляется, запись поднимается наверх с новым временем.
- [x] Построить 21 разный отчёт → в истории ровно 20 записей, самая старая вытеснена.
- [x] Клик по записи режима «ссылка» (в т.ч. с экрана «Проект») → открыт экран «Проекты», в поле ссылки подставлен URL записи, фокус в этом поле. (смоук)
- [x] Клик по записи режима «агрегат» → открыт экран «Проект»: заголовок — путь проекта (`group/project`, не имя), ветка, «Сколько пайплайнов» и статусы — из записи, кнопка «Агрегат по N пайплайнам» с N из записи.
- [x] Запись агрегата со статусом «любой» → «любой» отмечен, остальные чекбоксы сняты и неактивны.
- [x] Кнопка «×» у записи → удаляется только эта запись, запись при этом не открывается; у кнопки доступное имя «Удалить из истории: <подпись>».
- [x] «Очистить» → диалог «Очистить историю запросов?»; «Отмена» → история не изменилась.
- [x] «Очистить» → подтвердить → «Пока пусто», кнопка «Очистить» скрыта.
- [x] Перезапустить приложение → история сохранилась (лежит в `app_data_dir`).
- [x] Записи истории не содержат токен: открыть `history.json` в каталоге данных приложения → только поля `mode`, `host`, `url`, `project`, `ref`, `source`, `last`, `statuses`, без токена.

### 1.2. Проекты: ссылка

- [x] Поле «Вставь ссылку на пайплайн или MR» с подсказкой `https://gitlab.example.com/group/project/-/pipelines/123…` и кнопкой «Построить».
- [x] Вставить ссылку `…/-/pipelines/<id>` → «Построить» → кнопка неактивна, текст меняется на «Загружаю 0 из 1…» → «Загружаю 1 из 1…»; открылось окно отчёта; кнопка вернула текст «Построить». (смоук)
- [x] Ссылка на MR `…/-/merge_requests/<iid>` → открыт отчёт по head-пайплайну MR.
- [x] Ссылка с хвостом (`…/-/pipelines/123/builds`, `?tab=…`) → отчёт строится.
- [x] Пустое поле или `foo` → под полем «Нужна ссылка вида https://<хост>/<группа>/<проект>/-/pipelines/<id> или …/-/merge_requests/<iid>», окно не открывается.
- [x] Ссылка на несуществующий пайплайн → «Пайплайн gid://gitlab/Ci::Pipeline/<id> в проекте <проект> на <хост> не найден» (формат id — как в 0.1.0).
- [x] Ссылка на чужой/несуществующий проект → «Проект <проект> на <хост> не найден или нет доступа».
- [x] MR без пайплайна → «У MR !<iid> в проекте <проект> нет пайплайна».
- [x] Ссылка на хост без токена (нет ни в хранилище, ни в `glab`, ни в env) → «Нет токена для <хост>: добавь его в форме (поле «Токен»)».
- [x] Отозванный токен → «GitLab <хост> ответил 401: токен недействителен или нет доступа».

### 1.3. Проекты: хост и токен

- [x] Нет сохранённых хостов → в списке «Хост» выбран «+ Добавить хост…», видна подсказка «Добавь токен для этого хоста, чтобы смотреть список проектов.» и подформа «Хост»/«Токен»/«Сохранить токен»; панели проектов нет.
- [x] Ввести хост и токен → «Сохранить токен» → поле токена очищено, в списке выбран `<хост> — токен сохранён`, подформа скрыта, появилась кнопка «Удалить токен» и список проектов. (смоук)
- [x] Поле токена — тип пароля, без автозаполнения и проверки орфографии.
- [x] Хост `https://gitlab.example.com/` → сохраняется как `gitlab.example.com`.
- [x] Хост `bad host!` → «Укажи хост GitLab, например gitlab.example.com», токен не сохранён.
- [x] Пустой токен или из пробелов → «Пустой токен».
- [x] Несколько сохранённых хостов → в списке по алфавиту, при запуске выбран первый.
- [x] Переключить хост в списке → список проектов перезагружается под новый хост, поле поиска очищено.
- [x] «Удалить токен» → диалог «Удалить токен для <хост>?»; «Отмена» → ничего не изменилось.
- [x] «Удалить токен» → подтвердить → хост пропал из списка, выбран первый оставшийся или «+ Добавить хост…».
- [x] Токен не виден в интерфейсе: после сохранения его нельзя прочитать ни в одном поле.
- [x] Хост без сохранённого токена, но с токеном в `glab` → сборка по ссылке работает (токен берётся из `glab config get token --host <хост>`).
- [x] Только `GITLAB_TOKEN` + `GITLAB_HOST=<хост>` в окружении (запуск из терминала) → сборка по ссылке на этот хост работает; на другой хост — «Нет токена для …».

### 1.4. Проекты: поиск и список

- [x] С сохранённым токеном → пока грузится, статус «Загрузка…»; затем список проектов, в которых пользователь участник, по последней активности.
- [x] Строка проекта → имя с группой, полный путь, чип основной ветки (если есть), «активность <относительное время>» («вчера», «3 дня назад» и т.п.).
- [x] Ввести текст в «Поиск проекта» (подсказка «Название или путь…») → запрос уходит через 300 мс после последнего нажатия, а не на каждую букву.
- [x] Быстро напечатать и стереть часть запроса → в списке результаты последнего запроса, без смешивания с ответами на промежуточные.
- [x] Поиск без совпадений → «Ничего не найдено».
- [x] Ввести поиск, открыть проект, «← Проекты» → текст поиска и список на месте.
- [x] Больше 20 проектов → под списком «Показать ещё»; клик → добавились следующие 20, старые остались; на последней странице кнопки нет.
- [x] Ошибка загрузки (например, отозванный токен) → текст ошибки над списком, «Показать ещё» скрыта.
- [x] Клик по проекту → экран «Проект».

### 1.5. Проект: ветка

- [x] Открыть проект из списка → заголовок — имя проекта, кнопка «← Проекты», в поле «Ветка» — основная ветка проекта.
- [x] Подсказки веток → до 20 штук, основная ветка первой.
- [x] Ввести часть имени ветки → подсказки обновляются через 300 мс по вхождению подстроки.
- [x] Выбрать другую ветку → список пайплайнов перезагружается для неё.
- [x] Очистить ветку → список пайплайнов по всем веткам.
- [x] Ввести ветку, которой нет в подсказках → принимается, пайплайнов нет → «Ничего не найдено».
- [x] Пока печатаешь ветку, список пайплайнов не перезагружается; перезагрузка — при выборе подсказки, по Enter или при уходе фокуса, если значение изменилось.
- [x] «← Проекты» → экран «Проекты».
- [x] Esc на экране «Проект» → экран «Проекты». (смоук)
- [x] Esc на экране «Проекты» → ничего не происходит.
- [x] На экране «Проект» открыт Combobox веток → первый Esc закрывает его, экран остаётся; второй Esc → «Проекты».

### 1.6. Проект: пайплайны

- [x] Список последних пайплайнов ветки, пока грузится — «Загрузка…».
- [x] Строка пайплайна → `#<iid>`, статус-пилюля (success — зелёная, running/pending — синяя, failed — красная, manual/canceled/skipped/created — жёлтая), заголовок коммита (или «—»), автор (или «—»), относительное время создания, длительность в формате формы (`45s`, `12m05s`, `1h02m`, «—» если нет).
- [x] Больше 20 пайплайнов → «Показать ещё» догружает следующие 20.
- [x] Клик по строке → строка неактивна, в ней «Загружаю…», затем «Загружаю N из M…»; открылось окно отчёта по этому пайплайну; статус в строке скрылся.
- [x] Ошибка сборки по строке → текст ошибки остаётся в этой строке красным, строка снова активна.
- [x] Открыть проект A, затем вернуться и открыть проект B → в списке только пайплайны B (запоздавший ответ A не подмешивается).
- [x] Ошибка загрузки списка → текст ошибки, «Показать ещё» скрыта.

### 1.7. Проект: агрегат

- [x] По умолчанию «Статусы»: отмечены SUCCESS и MANUAL; FAILED, CANCELED, RUNNING и «любой» сняты.
- [x] Отметить «любой» → остальные статусы сняты и неактивны; снять «любой» → статусы снова активны (все сняты).
- [x] Снять все статусы → «Агрегат по …» → под статусами «Выбери хотя бы один статус или «любой»».
- [x] «Сколько пайплайнов» по умолчанию 50, кнопка «Агрегат по 50 пайплайнам».
- [x] Ввести 120 → кнопка сразу «Агрегат по 120 пайплайнам»; очистить поле → «Агрегат по 0 пайплайнам»; ввести 1 → «Агрегат по 1 пайплайну», 21 → «Агрегат по 21 пайплайну» (склонение — отступление, раздел 4).
- [x] N = 0, 501, 2.5 или пусто → «Число пайплайнов — от 1 до 500», сборка не начинается.
- [x] N = 1 → агрегат по одному пайплайну строится.
- [x] N = 500 → проходит проверку (сборку можно прервать закрытием окна отчёта после открытия).
- [x] «Агрегат по 50 пайплайнам» на `master` → кнопка неактивна, «Загружаю N из 50…» растёт; открылось окно агрегата; кнопка вернула прежний текст. (смоук)
- [x] Фильтры, под которые не попал ни один пайплайн (ветка без пайплайнов + только CANCELED) → «Под фильтры не попал ни один пайплайн: проверь ветку и статусы» под кнопкой.
- [x] Нет сети или хост недоступен → «Не удалось связаться с GitLab <хост>: <текст ошибки>».
- [x] Статусы и N, изменённые в проекте A, сохраняются при открытии проекта B; меняет их только запись истории.
- [x] Перезапуск приложения → N снова 50, статусы по умолчанию.

### 1.8. Язык

- [x] Системная локаль `ru*` → при первом запуске форма и меню на русском; любая другая → на английском.
- [x] Переключатель «RU / EN» в форме → форма сразу перерисовывается на выбранном языке без перезапуска. (смоук)
- [x] После переключения → меню приложения пересобрано на новом языке.
- [x] Окна отчётов, открытые до переключения, не меняют язык.
- [x] Отчёт, построенный после переключения на EN, открывается на английском.
- [x] Перезапуск → выбранный язык сохранился (`settings.json` в `app_data_dir`).
- [x] На EN ошибки валидации и GitLab (неверная ссылка, N вне диапазона, нет статусов, 401, проект не найден) — по-английски; текст GraphQL-ошибки от GitLab приходит как есть внутри английской фразы.
- [x] На EN относительное время, даты и числа — в английском формате; длительности (`12s`, `1m05s`) те же, что на RU.
- [x] Вычитка: пройти все экраны формы на EN → нет русских строк, ключей словаря вместо текста, обрезанных подписей.

## 2. Отчёт

Проверять на трёх отчётах: одиночный пайплайн (по ссылке), он же открытый из агрегата, агрегат по 50 пайплайнам.

### 2.1. Шапка

- [x] Одиночный → заголовок `<проект> · #<iid>`, `#<iid>` — ссылка на пайплайн в GitLab.
- [x] Одиночный → чипы: ref, статус, «<длина> длина», «ретраи <время>», «можно сэкономить до <время>», «<N> джоб/джобы/джоба» (склонение по числу).
- [x] Агрегат → заголовок `<проект> · <ветка>` (без ветки — «все пайплайны»), без ссылки.
- [x] Агрегат → чип «<N> пайплайнов (<k> success, <m> manual)» со склонением и счётчиками статусов в нижнем регистре; чип «<p50> · <p90> длина p50 · p90».
- [x] Чип «ретраи» красный при потерях > 0, обычный при `0s`; «можно сэкономить до» оранжевый при > 0.
- [x] «можно сэкономить до» = сумма пунктов «Куда направить силы».
- [x] Заголовок окна отчёта — `<проект> · <метка>`, не меняется при переходах внутри отчёта; во вкладке браузера у сохранённого файла — `longpole · <заголовок>`.
- [x] Кнопки «← к агрегату» нет в агрегате и в отчёте по ссылке.

### 2.2. «Куда направить силы»

- [x] Карточка «Куда направить силы» → не больше 3 пунктов, каждый с экономией от 10 с, по убыванию экономии.
- [x] Нет кандидатов → карточки нет вовсе.
- [x] Пункт → «−<экономия> <джоба> — <причина>».
- [x] Причина превышения в одиночном → «стейдж <S> ждёт её <время> после остальных, на критическом пути»; в агрегате — без «, на критическом пути».
- [x] Причина ретраев в одиночном → «<n> упавшая попытка / упавшие попытки / упавших попыток»; в пайплайне, открытом из агрегата, добавлено «, ретраи в k из N последних».
- [x] Причина ретраев в агрегате → «ретраи в k из N пайплайнов».
- [x] В карточку попадают только джобы критического пути.
- [x] Клик по пункту → джоба выделена, свёрнутая группа с ней развернута, строка прокручена в центр и в фокусе, открыта панель.

### 2.3. Водопад: ось

- [x] Ось начинается с `0s` (создание пайплайна), деления не чаще 10 на видимый интервал, шаг из ряда 1s, 5s, 10s, 30s, 1m, 2m, 5m, 10m, 15m, 30m, 1h, 2h.
- [x] Подписи делений в формате отчёта (`30.0s`, `1m00s`, `1h00m`), при зуме шаг мельчает.

### 2.4. Водопад: карточки стейджей

- [x] Каждый стейдж — карточка с заголовком-строкой стейджа.
- [x] Одиночный → в заголовке «длина <X>» (от старта первой джобы до конца последней) и «до конца <X>» (от создания пайплайна).
- [x] Агрегат → «длина <p50> · <p90>», «до конца <p50> · <p90>», подсказка при наведении «p50 · p90».
- [x] Стейдж с узким местом → в начале «держит <джоба> +<превышение>».
- [x] Незапущенный стейдж в одиночном → без «длина»/«до конца».
- [x] Downstream-пайплайн внутри bridge → строки дочернего пайплайна разрывают карточку стейджа, остаток стейджа продолжается карточкой без заголовка.

### 2.5. Водопад: строки

- [x] Иерархия: пайплайн → стейджи → группы/джобы → bridge → дочерний пайплайн; отступ растёт с глубиной.
- [x] При открытии отчёта все группы шардов свёрнуты, у группы `▸` и число детей.
- [x] Клик по `▸` → группа развёрнута, `▾`; повторный клик сворачивает; клик по стрелке не выделяет строку.
- [x] У стрелки доступное имя «Развернуть <имя>» / «Свернуть <имя>».
- [x] Джоба, которая ждала соседа по стейджу, стоит сразу после него с подписью «← <сосед>».
- [x] Длинное имя обрезано, полное — в подсказке при наведении.
- [x] Справа у джобы в агрегате и в пайплайне из агрегата — метка стабильности: «стабильна» (зелёная), «↻ k из N» жёлтая (< 30% запусков) или красная (≥ 30%), подсказка «ретраи в k из N пайплайнов».
- [x] В пайплайне, открытом по ссылке (без агрегата), меток стабильности нет.
- [x] Строки критического пути выделены оранжевым; группа выделена, если на пути её шард.
- [x] Агрегат → выделены узлы, бывшие на критическом пути в ≥ 50% пайплайнов.

## 7. Первый запуск: «Мои проекты», отчёт в окне, настройки

Спека — `docs/specs/2026-10-06-first-run-ux-design.md`. Проходится на macOS в dev-сборке с чистым каталогом данных приложения; пункты `(смоук)` — на Windows и Linux.

### 7.1. Пустое состояние и добавление

- [ ] Чистый каталог данных → в центре «Добавь первый проект» с кнопкой, в сайдбаре «Мои проекты» пусто, «Недавние» — «Пока пусто», в шапке поле ссылки и шестерёнка. (смоук)
- [ ] «+ Добавить проект» → диалог с одним полем, «Выбрать папку…», «Найти в списке проектов хоста».
- [ ] Вставить `https://<хост>/<группа>/<проект>` при отсутствии токена → под полем «Нужен токен для <хост>», ссылка «Создать на <хост> ↗» открывает системный браузер на странице токенов с именем `longpole` и scope `read_api`.
- [ ] Ввести неверный токен → «GitLab <хост> ответил 401…», введённая ссылка на месте.
- [ ] Ввести верный токен → проект в «Мои проекты», открыт экран проекта, диалог закрыт. (смоук)
- [ ] Ссылка на несуществующий проект → «Проект … не найден или нет доступа».
- [ ] «foo» → «Не похоже на ссылку на проект GitLab или путь к папке».
- [ ] «Выбрать папку…» с клоном (https- и ssh-remote) → проект добавлен; папка без git → «В папке нет git-репозитория с remote origin».
- [ ] «Найти в списке проектов хоста» → хост, поиск, «Показать ещё»; клик по строке добавляет проект.
- [ ] Повторное добавление того же проекта → дубля нет, проект на прежнем месте.
- [ ] Крестик у проекта в сайдбаре → проект убран без подтверждения; доступное имя «Убрать из списка: <имя>».
- [ ] ⌘⇧N открывает диалог, Esc закрывает его (второй Esc ничего не делает на экране проекта).
- [ ] Ссылка на пайплайн незнакомого хоста в шапке → блок токена под полем; после сохранения сборка стартует сама.

### 7.2. Отчёт в окне

- [ ] Клик по пайплайну → отчёт в том же окне без сайдбара, сверху «← Назад» и `<проект> · #<iid>`; переключателя RU/EN в шапке отчёта нет. (смоук)
- [ ] Водопад, панель деталей, клавиши `[`, `]`, `0`, ↑/↓, Enter, ←/→, Esc (снятие выделения) — как в разделе 2.
- [ ] Выделить строку → Esc снимает выделение и остаётся на отчёте; второй Esc → назад.
- [ ] «← Назад» и Esc (без выделенной строки) → экран проекта, список пайплайнов на месте.
- [ ] ⌘S на отчёте → диалог сохранения с именем `longpole-<проект>-<суффикс>.html`; файл открывается в браузере, в нём есть RU/EN. (смоук)
- [ ] ⌘S на экране проекта или настроек → ничего не происходит.
- [ ] Клик по записи в «Недавних» сразу после сборки → отчёт мгновенно, без «Загружаю…»; после 11 новых сборок самая старая запись строит заново с прогрессом.
- [ ] Язык RU→EN в настройках → открытый затем отчёт на английском; тема «Тёмная» → отчёт тёмный; сохранённый файл следует теме системы.
- [ ] Ссылка «GitLab ↗» в панели деталей открывает системный браузер.

### 7.3. Настройки и запуск

- [ ] Шестерёнка и ⌘, → экран настроек; Esc и «← Назад» возвращают. (смоук)
- [ ] Хосты: источник «связка ключей» с кнопкой «Удалить токен» и подтверждением; хост из `glab` — источник «glab» без кнопки; `GITLAB_TOKEN`+`GITLAB_HOST` — «переменные окружения» без кнопки.
- [ ] «Добавить хост» → форма хост+токен; после сохранения хост в таблице.
- [ ] Тема: «Светлая» и «Тёмная» применяются сразу и переживают перезапуск; «Системная» следует смене темы ОС на лету.
- [ ] Перезапуск приложения → открыт последний открытый проект; убрать его из списка и перезапустить → открыт первый из оставшихся; убрать все → пустое состояние. (смоук)
- [ ] `settings.json` содержит `locale`, `theme`, `lastProject`; `projects.json` — `host`, `path`, `name`, `addedAt`; токенов в них нет.
- [ ] Linux без Secret Service: под таблицей хостов подсказка (`form.settings.linuxHint`) про Secret Service, `glab` и `GITLAB_TOKEN`/`GITLAB_HOST`, добавление по ссылке с вводом токена даёт «Системная связка ключей недоступна…».
