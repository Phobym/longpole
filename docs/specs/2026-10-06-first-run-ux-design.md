# Первый запуск: проекты, отчёт в окне, настройки — спека

Дата: 2026-10-06. Переработка первого пользовательского опыта приложения. Базовая спека — `docs/specs/2026-10-03-tauri-rewrite-design.md`; здесь только отличия от неё. Макеты обсуждения — `.superpowers/brainstorm/` (не коммитятся).

## 1. Цель и рамки

Новый пользователь ставит приложение, вставляет ссылку на репозиторий или пайплайн, вводит токен по подсказке и видит отчёт, не покидая окна. Два равноценных входа: ссылка на пайплайн/MR и «свой» проект.

Делается:

- «Мои проекты» вместо поиска по всем проектам хоста на первом экране; добавление по ссылке, по папке с клоном или из списка хоста.
- Отчёт рендерится в главном окне, отдельные окна отчётов удаляются.
- Экран настроек: хосты и токены, тема, язык.
- Токен запрашивается в месте, где он понадобился, с ссылкой на создание.

Не делается: онбординг-туры (подсказки по событиям — см. 2026-10-08-onboarding-design.md), подсказки по клавишам, GitHub, несколько окон отчётов, drag-and-drop папок, синхронизация списка проектов между машинами, автотесты фронтенда.

## 2. Раскладка и навигация

Одно окно `form`, TanStack Router, hash history.

| Маршрут | Экран |
|---|---|
| `/` | Нет проектов — пустое состояние «Добавь первый проект» с кнопкой. Есть — редирект на последний открытый проект (`settings.lastProject`), если он ещё в списке, иначе на первый. |
| `/project/$host/$` | Экран проекта как сейчас: ветка, последние пайплайны, агрегат. Вход на маршрут записывает `lastProject`. |
| `/report/$id` | Отчёт. Новый. |
| `/settings` | Настройки. Новый. |

**Сайдбар** (w-72, как сейчас) заменяет `history-sidebar`:

- «Мои проекты»: список из `projects.json`, активный подсвечен, по наведению крестик «убрать из списка» без подтверждения. Кнопка «+ Добавить».
- «Недавние»: записи `history.json` (20, те же удалить/очистить, тот же повтор по клику).

**Шапка**: поле «Вставь ссылку на пайплайн или MR» + «Построить» (нынешний `build-by-link`), справа шестерёнка. Переключатель языка из шапки удаляется.

**Экран отчёта** прячет сайдбар и поле ссылки. В шапке: «← Назад» и заголовок отчёта (`meta.project` + `meta.label` на текущем языке). Esc и «← Назад» — `history.back()`. Корневой обработчик Esc остаётся один; правило «первый Esc закрывает оверлей» сохраняется.

**Клавиши**: ⌘⇧N — «Добавить проект», ⌘, — настройки (Ctrl на Windows/Linux), ⌘S — сохранить текущий отчёт. Пункты меню «Файл»: «Новый отчёт» ⌘N — фокус на окно, как сейчас; «Сохранить отчёт…» ⌘S.

## 3. «Мои проекты»

### Хранение

`projects.json` в `app_data_dir`, без секретов:

```json
[{ "host": "gitlab.example.com", "path": "group/project", "name": "project", "addedAt": "2026-10-06T10:00:00Z" }]
```

Порядок — порядок добавления. Дедупликация по `[host, path]`. Модуль `core::projects` по образцу `core::history` (`json_file`).

### Диалог «Добавить проект»

Открывается из сайдбара, пустого состояния и по ⌘⇧N. Одно поле, кнопка «Выбрать папку…» (`plugin-dialog`, `open` с `directory: true`), ссылка «Найти в списке проектов хоста».

**Разбор ввода** — `core::request::parse_project_input(input) -> Result<ProjectRef, Error>`, где `ProjectRef { host, path }`. Принимает:

- `https://host/group/project`, с `.git` и без, с завершающим `/`;
- ссылки на пайплайн и MR (переиспользует нынешний разбор `…/-/pipelines/<id>` и `…/-/merge_requests/<iid>`);
- `git@host:group/project.git`, `ssh://git@host[:port]/group/project.git`;
- абсолютный путь к папке: читает `<dir>/.git/config` (или файл `.git` с `gitdir:` для worktree), секцию `[remote "origin"]`, `url`, разбирает по правилам выше.

Хост нормализуется как в `TokenStore::set` (без схемы и завершающего `/`). Ошибки по полю `input`: `project_input_invalid`, `project_dir_no_remote`.

**Проверка доступа** — команда `add_project(input) -> Result<SavedProject, CmdError>`:

1. `parse_project_input`;
2. `client_for(host)`; нет токена — `CmdError { code: token_missing, params: { host } }`, фронтенд раскрывает блок токена;
3. GraphQL `project(fullPath)` — существующий запрос `browse`; `null` или 404 — `project_not_found`; 401 — `token_rejected`;
4. запись в `projects.json`, возврат записи.

Успех: диалог закрывается, навигация на экран проекта. Ошибка: текст под полем, введённое остаётся.

**Блок токена** (`features/manage-token`, переиспользуется в шапке и в настройках):

- заголовок «Нужен токен для {host}»;
- ссылка «Создать на {host}» → `https://{host}/-/user_settings/personal_access_tokens?name=longpole&scopes=read_api`, через `opener`;
- поле токена (`type=password`), подпись «Хранится в системной связке ключей»;
- «Сохранить» → `set_token`, затем повтор исходного действия (добавление проекта или сборка по ссылке).

Ссылка на пайплайн/MR с незнакомого хоста в шапке показывает тот же блок под полем.

**«Найти в списке проектов хоста»** разворачивает внутри диалога нынешний `projects-panel` (выбор хоста, поиск, «Показать ещё»). Клик по строке — `add_project` с `https://host/path`.

### Хосты с токеном из `glab` и окружения

Команда `hosts` возвращает `{ host, source: 'keychain' | 'glab' | 'env' }[]`. `glab` — хост по умолчанию из `glab config get host`, если токен для него находится; `env` — `GITLAB_HOST` при заданном `GITLAB_TOKEN`. Для таких хостов блок токена не показывается, «Удалить» в настройках недоступно.

## 4. Отчёт в окне

- `build(form, onProgress) -> Result<u32, CmdError>` возвращает `id` отчёта. Rust держит `AppState.reports` — `VecDeque` на 10 записей `{ id, report: Report, html: String, file_name: String }`, вытесняется самая старая (FIFO). Запись истории — как сейчас.
- `report(id) -> Result<String, CmdError>` возвращает JSON-строку `Report`, фронтенд парсит её; нет записи — `report_expired`, фронтенд уходит на `/`.
- Повтор из «Недавних»: ключ `[host, request]` хранится рядом с отчётом; если запись в кеше, фронтенд сразу открывает `/report/$id` (команда `find_report(host, request) -> Option<u32>`), иначе `build` как сейчас.
- `/report/$id` рендерит `<ReportPage report={…}/>` из `pages/report`. `ReportHeader` получает флаг `embedded`: без переключателя языка. Локаль — текущая i18next, тема — класс на корне (§ 5).
- `set_current_report(id | null)` вызывается при монтировании и размонтировании экрана отчёта. «Сохранить отчёт…» пишет `html` текущего через `save_file` с `file_name`; нет текущего — ничего.
- Второй вход `app/report/main.tsx` и `vite.report.config.ts` остаются: они собирают шаблон сохраняемого HTML. `render` не меняется.
- Ссылки `https` из отчёта внутри окна `form` открываются `on_navigation` → `opener`, как в форме.

Удаляется: схема `report://`, `create_report`, capability-изоляция окон отчётов, учёт последнего сфокусированного окна, `all_pipelines` в `strings.rs`, заголовок окна отчёта. CSP формы не меняется.

## 5. Настройки

`/settings`, шестерёнка, ⌘,. Esc — назад. Три блока на одной странице.

**Хосты и токены**: таблица из `hosts`: хост, источник, «Удалить» (только `keychain`, с подтверждением как сейчас). «Добавить хост» открывает блок токена из § 3. Подсказка про Linux без Secret Service остаётся.

**Тема**: «Системная», «Светлая», «Тёмная». `settings.theme: 'system' | 'light' | 'dark'`, дефолт `system`. Применение: класс `dark` на `<html>`; `system` ставит класс по `matchMedia('(prefers-color-scheme: dark)')` и слушает изменения. `theme.css`: медиазапрос заменяется на `.dark`, `color-scheme` выставляется тем же классом. Сохранённый HTML-отчёт следует системе, как сейчас.

**Язык**: нынешний `LanguageSwitch` без изменений.

**Команды**: `get_settings() -> Settings`, `set_settings(patch: Partial<Settings>) -> Settings`, где `Settings { locale, theme, lastProject: { host, path } | null }`. `get_locale`/`set_locale` удаляются; `set_settings` с `locale` пересобирает меню.

## 6. Ошибки

Коды в enum `ErrorCode`, перевод во фронтенде; `tsc` падает, пока нет перевода.

| Код | Текст (ru) |
|---|---|
| `projectInputInvalid` | Не похоже на ссылку на проект GitLab или путь к папке |
| `projectDirNoRemote` | В папке нет git-репозитория с remote `origin` |
| `projectNotFound` (существующий) | Проект {project} на {host} не найден или нет доступа |
| `noToken` (существующий, текст меняется) | Нужен токен для {host} |
| `unauthorized` (существующий) | GitLab {host} ответил {status}: токен недействителен или нет доступа |
| `reportExpired` | Отчёт больше не в памяти, построй заново |

## 7. Тесты

`cargo test -p longpole-core`:

- `request`: `parse_project_input` — https с `.git` и без, завершающий `/`, ссылка на пайплайн и MR, `git@`, `ssh://` с портом, папка с `.git/config` (tempdir), worktree с файлом `.git`, папка без remote, мусор.
- `projects`: добавление, дедупликация, удаление, round-trip JSON.
- `settings`: `theme` и `lastProject` с дефолтами, чтение старого файла только с `locale`.
- `src-tauri`: вытеснение из `reports` при 11-й записи.

Чек-лист приёмки (дополнение к `2026-10-03-tauri-rewrite-acceptance.md`): чистый каталог данных → пустое состояние → добавление по ссылке с вводом токена → проект → отчёт в окне → ⌘S → «← Назад» → добавление по папке → добавление из списка → смена темы и языка → перезапуск открывает последний проект → повтор из «Недавних» без прогресса.
