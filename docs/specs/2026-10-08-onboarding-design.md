# Онбординг по событиям и маскот-жираф — спека

Дата: 2026-10-08. Подсказки появляются в момент, когда пользователь впервые встречает элемент или явление, а не туром по списку. Маскот — жираф с иконки приложения: шея из полосок трейса. Базовые спеки — `2026-10-06-first-run-ux-design.md` и `2026-10-06-native-redesign-design.md`; эта спека отменяет в них два пункта: «онбординг-туры не делаются» и «анимаций не добавляем» (§ 3, § 4). Макеты обсуждения — `.superpowers/brainstorm/` (не коммитятся).

## 1. Цель и рамки

Новый пользователь понимает, что куда вставлять (ссылка, токен, проект) и как читать отчёт (критический путь, «Куда направить силы», ретраи, агрегат), не открывая README.

Делается:

- подсказки с жирафом у элемента (coach-mark), запускаемые событиями приложения;
- компонент жирафа с тремя позами; жираф в пустых состояниях, загрузке отчёта и inline-ошибках;
- настройки «Показывать подсказки» и «Показать заново».

Не делается: линейные туры с «Дальше», подсказки в сохранённом HTML-отчёте, жираф в системных окнах `showError` (plugin-dialog не принимает картинки), аналитика показов, библиотеки туров.

## 2. Каталог подсказок

Порядок строк внутри экрана — приоритет. Вид `enter` — подсказка готова, пока открыт экран или элемент; `event` — готова в момент действия пользователя.

**Приложение**

| id | Вид | Событие (`when`) | Якорь | Суть текста |
|---|---|---|---|---|
| `add-project.input` | event | диалог «Добавить проект» открыт | поле ввода | подойдёт ссылка на репо, пайплайн или MR, ssh-адрес или папка с клоном |
| `token.create` | event | блок токена показан | ссылка «Создать на {host}» | откроется страница создания токена с нужными правами; хранится в связке ключей |
| `project.screen` | enter | экран проекта открыт | кнопка агрегата | клик по пайплайну — отчёт по одному; агрегат — по N пайплайнам, p50/p90 |
| `project.workflow` | enter | экран GitHub-проекта открыт; `after: project.screen` | выбор workflow | запуски и агрегат строятся по одному workflow |
| `header.link` | event | первый возврат с экрана отчёта | поле ссылки в шапке | в следующий раз можно сразу вставить ссылку на пайплайн, MR, run или PR |

**Отчёт в окне**

| id | Вид | Событие (`when`) | Якорь | Суть текста |
|---|---|---|---|---|
| `report.hotspots` | enter | отчёт открыт, карточка «Куда направить силы» есть | карточка | здесь только джобы критического пути: ускорение остальных пайплайн не сократит |
| `report.critical` | enter | отчёт открыт; `after: report.hotspots` | первая полоска критического пути | оранжевое — критический путь; клик по стейджу пересчитывает путь до его конца |
| `report.keys` | enter | отчёт открыт; `after: report.critical` | кнопка `?` | ⌘/Ctrl + колесо — масштаб, `[` `]` — сдвиг, `0` — весь пайплайн, `?` — все клавиши |
| `report.retries` | enter | в отчёте есть джоба с ретраями | первая строка с ретраем | красная штриховка — упавшие попытки, `↻2 −8m29s` — сколько на них потеряно |
| `report.aggregate` | enter | агрегатный отчёт | первая метка стабильности | полоска — p50, линия после неё — до p90; метка — доля запусков с ретраями |
| `report.detail` | event | первый выбор джобы | шапка панели деталей | сверху вывод; ниже связи ↑/↓; Esc снимает выбор |

Цепочка `report.hotspots` → `report.critical` → `report.keys` через `after` и правило «одна `enter` за визит» (§ 4) даёт первую подсказку на первом отчёте, вторую — на втором, третью — на третьем, без счётчиков.

Если в отчёте нет карточки «Куда направить силы» (нет пунктов от 10 с), `report.hotspots` не готова, и `report.critical`/`report.keys` ждут отчёта, где карточка есть. Это допустимо: цепочка не главная.

## 3. Жираф

### Компонент

`shared/ui/giraffe.tsx` — `<Giraffe pose size className />`, inline SVG на геометрии `app/src-tauri/icons/app-icon.svg` без оранжевой подложки: силуэт цвета `mascot`, шея — 4 полоски с непрозрачностью `.55 / .7 / .85 / 1` снизу вверх, глаз `#1c2333`. `aria-hidden`: смысл несёт текст рядом.

| Поза | Где | Отличие |
|---|---|---|
| `idle` | подсказки, пустые состояния | как на иконке |
| `loading` | сборка отчёта и агрегата | prop `progress?: { loaded, total }`: полностью непрозрачны `ceil(4 · loaded / total)` полосок, остальные `.2`; без `progress` полоски загораются по кругу шагом 300 мс |
| `oops` | inline-ошибки | голова повёрнута вниз на 20°, глаз — короткая дуга |

### Токены

В `theme.css`, `:root` и `:root.dark`:

| Токен | Светлая | Тёмная |
|---|---|---|
| `mascot` | `#e8701a` | `#ff8a3d` |
| `mascot-bg` | `#fff4e8` | `#2e2216` |
| `mascot-border` | `#f2c79c` | `#5a3d10` |

Текст подсказки — `foreground`, выделенные слова — `crit-fg`; оба ≥ 4,5:1 на `mascot-bg` в обеих темах. Проверяется при реализации; при недоборе `mascot-bg` светлеет (светлая тема) или темнеет (тёмная).

### Где живёт

- Подсказка — § 4, жираф `idle` 56px слева от текста.
- Главный экран без проектов — `idle` 120px над заголовком `form.empty.title`.
- Экран проекта, в ветке нет пайплайнов — `idle` 72px над текстом пустого списка.
- Пустые «Недавние» в сайдбаре — `idle` 32px слева от текста.
- Прогресс сборки отчёта и агрегата — `loading` 72px на месте нынешнего индикатора, с `Progress` из команды.
- Inline-ошибки: под полем «Добавить проект», в блоке токена, на `reportExpired` — `oops` 40px слева от текста.

## 4. Механика

### Модуль `features/onboarding`

- `model/tips.ts` — реестр: массив `{ id, kind: 'enter' | 'event', after?: TipId }` в порядке приоритета; `TipId` — union из id. Тексты — ключи `onboarding.<id>.title` и `onboarding.<id>.text` во всех 8 локалях.
- `model/pick.ts` — чистая функция `pickTip(ready, settings, visit, active) -> TipId | null`.
- `model/store.ts` — zustand: `ready: Set<TipId>`, `active: TipId | null`, `visit: { enterShown: boolean }`, `leftReport: boolean`.
- `ui/Tip.tsx` — обёртка `<Tip id when>{child}</Tip>`.
- `ui/TipBubble.tsx` — содержимое: жираф, заголовок, текст, «Понятно», «Больше не показывать».

Публичный API (`index.ts`): `Tip`, `useOnboardingVisit()`, `markLeftReport()`.

### Выбор подсказки

`pickTip` возвращает `null`, если `active` не пуст или `settings.tips === false`. Иначе кандидаты — `ready` минус `settings.seenTips` минус те, чья `after` не в `seenTips`:

- `event` — выбирается первая по порядку реестра, независимо от `enterShown`;
- `enter` — только если `visit.enterShown === false`; первая по порядку реестра. После показа `enterShown = true`.

`event` приоритетнее `enter`: он отвечает на действие пользователя прямо сейчас.

**Визит** — монтирование экрана: `useOnboardingVisit()` в `HomePage`, `ProjectPage`, `ReportPage` и `SettingsPage` сбрасывает `visit.enterShown` при монтировании. Открытие диалога визит не сбрасывает; подсказки диалога и блока токена — `event`, поэтому показываются независимо от `enterShown`.

`header.link`: `ReportPage` при размонтировании вызывает `markLeftReport()`; в шапке `<Tip id="header.link" when={leftReport}>`.

### `<Tip>`

1. Пока `when` истинно и `id` не в `seenTips`, `<Tip>` держит `id` в `ready`; при `when === false` или размонтировании убирает, и если был `active`, `active = null`.
2. Стор после каждого изменения `ready` и `active` вызывает `pickTip`; результат — новый `active`.
3. В момент, когда подсказка становится `active`, её `id` добавляется в `seenTips` через `useUpdateSettings` — просмотрено по факту показа, без повторов при быстром закрытии диалога.
4. Разметка: `Popover open={active === id}` + `PopoverAnchor asChild` вокруг ребёнка + `PopoverContent` с `TipBubble`. Поповер живёт в дереве компонента, а не в корне приложения: внутри модального Radix `Dialog` поповер из корня не получает кликов и фокуса.
5. Якорь получает `data-tip-active` → обводка 2px `mascot`, `outline-offset: 2px`.

`PopoverContent`:

- `onOpenAutoFocus` → `preventDefault`: фокус остаётся в поле;
- `onInteractOutside` → `preventDefault`: клик мимо не закрывает;
- Esc закрывает подсказку (`active = null`), не диалог — слои Radix; корневой обработчик Esc приложения считает открытую подсказку оверлеем: первый Esc закрывает её;
- «Понятно» — `active = null`; «Больше не показывать» — `set_settings({ tips: false })` и `active = null`;
- ширина 300px, фон `mascot-bg`, рамка `mascot-border`, сторону выбирает Radix, `collisionPadding: 8`;
- появление — opacity + scale `.96 → 1`, 150 мс; при `prefers-reduced-motion: reduce` без анимации. То же для полосок позы `loading`.

Закрытая подсказка в текущий визит не показывается снова: она уже в `seenTips`.

### Хранение

Rust, `core::settings`: в `AppSettings` поля `tips: bool` (по умолчанию `true`) и `seen_tips: Vec<String>` (по умолчанию пусто, в JSON — `seenTips`), оба через `#[serde(default…)]`. `SettingsPatch` — те же поля опциональными. Старый `settings.json` читается без миграции. Ядро id не проверяет. Типы фронтенда — перегенерация ts-rs.

Пример `settings.json`:

```json
{ "locale": "ru", "theme": "system", "lastProject": null, "tips": true, "seenTips": ["add-project.input", "report.hotspots"] }
```

### Настройки

Блок «Подсказки» на `/settings` между «Темой» и «Языком»: переключатель «Показывать подсказки» (`tips`) и кнопка «Показать заново» (`seenTips: []`, `tips: true`).

## 5. Тесты

`cargo test -p longpole-core`, `settings`:

- старый файл без `tips` и `seenTips` → `true` и `[]`;
- патч `tips` и `seenTips` — round-trip через файл.

Фронтенд: `app/src/features/onboarding/model/pick.test.ts` на `node:test` (Node 24 снимает типы сам), скрипт `"test:onboarding": "node --test src/features/onboarding/model/pick.test.ts"`, новых зависимостей нет. Случаи:

- две `enter` готовы — выбрана первая по реестру;
- `enterShown` — вторая `enter` за визит не выбирается;
- `event` выбирается при `enterShown` и раньше готовой `enter`;
- есть `active` — `null`;
- `after` не просмотрена — не выбирается;
- `seenTips` содержит id — не выбирается;
- `tips: false` — `null`.

`check:locales` и `tsc` ловят отсутствующие ключи `onboarding.*`.

Чек-лист приёмки (дополнение к `2026-10-03-tauri-rewrite-acceptance.md`): чистый каталог данных → жираф в пустом состоянии → диалог добавления → `add-project.input`, ввод не прерывается → блок токена → `token.create` → экран проекта → `project.screen` (у GitHub-проекта на следующем визите — `project.workflow`) → сборка: жираф `loading` → `report.hotspots` → выбор джобы → `report.detail` → «← Назад» → `header.link` → второй отчёт → `report.critical` → третий → `report.keys` → отчёт с ретраями → `report.retries` → агрегат → `report.aggregate` → Esc в диалоге закрывает подсказку, а не диалог → «Больше не показывать» → подсказок нет → «Показать заново» → снова есть → неверный токен → жираф `oops` → тёмная тема → `prefers-reduced-motion`.

## 7. Отступления при реализации

- `reportExpired` показывается системным окном — жираф `oops` только под полем «Добавить проект» и в блоке токена.
- `token.create` привязана ко всему блоку токена: `features/manage-token` не может импортировать `features/onboarding`. В шапке подсказка токена молчит, пока открыт диалог добавления проекта: у подсказки один якорь.
- Жираф `loading` — у кнопки агрегата и на экране загрузки отчёта; в кнопке «Построить» шапки и в строке пайплайна — прежний текст прогресса.
- Esc: подсказка гасит распространение в `onEscapeKeyDown`; корневой обработчик и `useReportKeys` не меняются.
- Визит отмечают `ProjectPage` и `ReportPage`; `startVisit` не сбрасывает «enter уже была», если enter-подсказка этого экрана уже открыта (эффекты якорей идут раньше эффекта страницы).
- Активная подсказка уходит при размонтировании якоря через микротаск (StrictMode).
- Настройки читаются в стор один раз при запуске; дальше стор — источник правды и сам пишет `tips`/`seenTips`. Просмотренные при чтении объединяются; «Показать заново» — явный сброс.
- `<Tip>` всегда рендерит Popover: `when` только разрешает регистрацию и показ, якорь не перемонтируется. У пузыря доступное имя (`aria-labelledby` на заголовок).
- В водопаде один `<Tip>` на строку (якорь — строка): строке достаётся первая непросмотренная из `report.critical`, `report.retries`, `report.aggregate`, открытая держится, пока открыта.
- Обводка якоря `[data-tip-active]` — вне слоёв CSS, чтобы перебить `focus-ring`. `PagedList` всегда держит свою aria-live-строку, жираф пустого списка — декорация рядом.
